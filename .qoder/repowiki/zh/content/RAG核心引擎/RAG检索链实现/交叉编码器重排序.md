## 简介
本技术文档围绕"交叉编码器重排序"（Cross-Encoder Reranker）展开，系统阐述其在检索增强生成（RAG）链路中的作用、实现细节、性能优化策略与工程实践。重点包括：
- Cross-Encoder 模型工作原理与 BAAI/bge-reranker-base 的选择理由
- 类级别缓存机制与模型加载/缓存管理
- 查询-文档对构建、相似度分数计算与结果排序算法
- RRF 融合与混合检索的整体流程
- 配置项解读、异常处理与性能优化建议
- 重排序对检索质量的提升、缓存策略的内存管理与局限性

## 详细组件分析

### Cross-Encoder 重排序器（Reranker）
- 工作原理
  - 将"查询-文档"对拼接为成对输入，调用 CrossEncoder.predict 计算相关性分数
  - 依据分数对候选进行降序排序，得到最终排序结果
- 性能优化特性
  - **类级别缓存**：避免每次查询重复加载模型，显著降低延迟
  - **top_n限制**：仅对前N个候选文档进行精排，大幅减少计算开销
  - **可配置开关**：通过 `reranker.enabled` 控制重排序启用/禁用
- 模型选择：BAAI/bge-reranker-base
  - 本地可加载、推理快速、中文场景表现良好，适合企业内部署
- 类级别缓存策略
  - 首次或模型名变更时加载；后续查询复用已加载模型，避免重复 IO
  - 缓存字段：_reranker_model、_reranker_model_name、_reranker_load_failed
- 本地路径离线加载
  - 支持从配置的 local_path 离线加载模型，提升部署灵活性
  - 优先使用本地路径，否则回退到 HuggingFace 模型名在线下载
- 异常处理
  - 捕获加载与预测异常，记录日志并跳过重排序，保证主流程可用

## 性能考量
- 类级别缓存
  - 避免重复加载模型，显著降低延迟与显存占用
  - 适用于高并发场景，建议保持模型版本稳定
  - 新增 _reranker_load_failed 标记，避免重复尝试失败的模型
- 预热机制
  - 后台线程异步加载，提升首屏体验
  - 前端轮询状态，加载完成后才允许查询
  - 支持配置启用/禁用，确保预热过程的可控性
- top_n处理限制
  - 仅对前N个候选文档进行精排，大幅减少 Cross-Encoder 计算量
  - 默认值10，可通过配置项调整
  - 显著提升查询性能，减少GPU/CPU负载
- 可配置激活开关
  - 通过 `reranker.enabled` 控制重排序启用/禁用
  - 禁用时可大幅加速响应，但可能降低检索精度
  - 适用于性能敏感场景或离线环境
- 检索与融合
  - 向量检索 + BM25 + RRF 融合，兼顾召回与排序稳定性
  - 距离阈值过滤低相关度，减少下游 LLM 负担
- 上下文构建与裁剪
  - 基于 token 估算与预算分配，动态裁剪内容，避免越界
- LLM 调用
  - 流式优先，失败自动降级为非流式；带指数退避重试
- **新增** 本地路径加载优化
  - 支持离线部署，避免网络依赖
  - 提升部署灵活性和安全性

  - 现象：首次查询耗时较长

  - 处理：检查配置文件中的 reranker 配置、确认模型路径正确
- **新增** 重排序性能问题
  - 现象：查询响应时间过长
  - 可能原因：top_n过大、模型未预热、enabled配置错误

- **新增** 本地路径加载失败
  - 现象：本地模型路径不存在或加载失败
  - 可能原因：local_path 配置错误、权限问题、模型文件损坏

  - 处理：检查向量库是否已入库、embedding 是否正常
- LLM 调用失败
  - 现象：流式/非流式均失败
  - 处理：检查 API 配置、网络连通性、重试策略

## 结论
交叉编码器重排序通过细粒度相关性打分，有效提升了检索质量与 LLM 生成的准确性。配合类级别缓存与预加载机制，系统在性能与稳定性方面达到良好平衡。**新增的重大性能优化包括**：
- **类级别模型缓存**：避免重复加载，显著降低延迟
- **预热机制**：后台线程预加载，提升首屏体验
- **可配置激活开关**：灵活控制重排序启用/禁用
- **top_n处理限制**：大幅减少计算开销，提升查询性能
- **本地路径离线加载**：进一步提升部署灵活性和安全性

- **新增** 根据性能需求调整 reranker.top_n 配置

- **新增** 通过 reranker.enabled 控制重排序，平衡性能与精度
