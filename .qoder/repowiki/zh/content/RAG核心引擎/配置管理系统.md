## 简介
本配置管理系统基于 YAML 配置文件与 Pydantic 类型验证，结合环境变量替换与单例模式，提供类型安全、可扩展且易于维护的配置能力。系统支持：
- 配置文件层次结构与默认值
- 环境变量注入与回退机制（${VAR} 与 ${VAR:-默认值}）
- 运行时配置热更新（通过强制重新加载）
- 组件间配置绑定与影响范围
- 审计日志开关与配置联动
- **新增**：构建打包配置选项 build_includes，支持灵活的文件包含策略
- **新增**：版本标准化管理，统一应用版本号获取和传递机制
- **新增**：增强的构建脚本支持，提升打包灵活性和可维护性
- **更新**：配置系统整体架构优化，增强版本管理和构建支持
- **更新**：配置参数优化，提升检索质量和性能

## 项目结构
配置相关的核心文件与职责如下：
- 配置文件：config.yaml（顶层 YAML 配置，包含环境变量占位符和 build_includes 配置）
- 配置解析与模型：rag/config.py（Pydantic 模型、环境变量替换、单例与加载、本地模型检测）
- 应用入口：app.py（读取配置、初始化 UI、日志与预加载）
- 日志与审计：rag/logging_config.py（结构化日志、审计日志）
- 向量库：rag/vectorstore.py（从配置创建向量库实例）
- 预加载：rag/preload.py（后台加载链，避免重复初始化）
- RAG链路：rag/chain.py（集成重排序模型的检索增强生成）
- 文档加载：rag/loader.py（从配置加载知识库文档）
- 认证服务：services/auth.py（用户注册、登录、密码管理、角色权限）
- 管理面板：ui/admin.py（管理员用户管理、聊天记录浏览、系统概览）
- 登录页面：ui/login.py（认证界面，支持登录/注册模式）
- 侧边栏：ui/sidebar.py（导航、会话管理、知识库文档树）
- 主题系统：ui/theme.py（企业级暗色/亮色双主题）
- 安装脚本：scripts/installer/linux/postinst.sh、scripts/installer/windows/write_config.py（系统集成与安装时写入）
- 运行时环境：run_app.py（自动检测和设置本地模型路径、版本跟踪）
- 构建脚本：scripts/build_linux.py、scripts/build_windows.py、scripts/build_installer.py（多平台构建支持）
- 测试：tests/test_config.py（环境变量替换、模型校验、文件加载）
- UI组件：ui/login.py、ui/sidebar.py（集成公司链接显示）
- 版本管理：rag/__init__.py（应用版本号获取）
- 打包配置：knowledge_app.spec（PyInstaller 打包规格文件）

## 核心组件
- **配置模型层（Pydantic）**：定义各子系统的配置结构、默认值与约束（如数值范围、枚举、字段间校验）。
- **环境变量替换**：支持 ${VAR} 与 ${VAR:-默认值} 两种语法，递归替换字典中的字符串值。
- **单例与加载**：提供 get_config()/reload_config()，确保全局唯一配置实例；from_yaml() 支持从文件加载并自动替换环境变量。
- **组件绑定**：UI 主题、日志与审计、向量库、预加载、RAG链路、文档加载、认证系统等均从全局配置读取关键参数。
- **构建配置管理**：新增 build_includes 配置选项，支持自定义构建打包时包含的文件和目录，提升打包灵活性。
- **版本标准化**：统一的应用版本号管理机制，确保构建、安装和运行时版本一致性。
- **认证系统**：新增用户认证配置，支持用户注册、登录、密码管理、角色权限控制。
- **Reranker配置**：增强的重排序模型配置，支持启用/禁用和Top-N控制，提升检索质量。
- **UI定制**：新增公司链接显示功能，支持企业级定制。
- **配置序列化优化**：load_config() 函数通过 Pydantic 内置 model_dump() 方法实现，提升代码简洁性。
- **本地模型检测**：新增 detect_local_models() 函数，支持扁平目录和HuggingFace缓存两种模型布局，自动设置环境变量。
- **版本跟踪**：通过 __version__ 变量和 config.yaml 中的版本号实现统一的版本管理。
- **配置参数优化**：更新距离阈值、分块大小和重叠参数，提升检索性能和质量。

### 配置文件结构与层次
- **顶层键**包括：model_root、llm、embedding、reranker、vectorstore、knowledge、rate_limit、auth、ui、max_conversation_turns、audit_enabled、admin_users、version、**build_includes** 等。
- **子模块键**：
  - **llm**：api_base、api_key（**已迁移到环境变量**）、model、temperature、max_tokens、context_window
  - **embedding**：model、local_path（支持环境变量覆盖）
  - **reranker**：model、local_path（支持环境变量覆盖）、enabled（**新增**）、top_n（**新增**）
  - **vectorstore**：persist_directory、collection_name、top_k、distance_threshold（**更新**：从1.5调整为2.0）
  - **knowledge**：docs_directory、chunk_size（**更新**：从500增加到1000）、chunk_overlap（**更新**：从50增加到100）
  - **auth**：enabled（**新增**）、users_file（**新增**）、min_password_length（**新增**）、admin_users（**新增**）
  - **ui**：title、subtitle、company_name、company_url（**新增**）、logo_text、default_theme
  - **version**：应用版本号（**新增**）
  - **build_includes**：构建打包时包含的文件和目录列表（**新增**）
  - **其他**：max_conversation_turns、audit_enabled、admin_users

**更新**：配置参数优化，提升检索性能和质量。距离阈值从1.5调整为2.0，允许更宽松的相似度匹配；chunk_size从500增加到1000，支持更大的文档分块；chunk_overlap从50增加到100，改善文档片段间的连续性。

**新增**：API密钥管理从config.yaml迁移到环境变量，提升安全性。新增${ENV_VAR:-default}语法支持，增强配置灵活性。新增认证系统配置和Reranker配置选项。新增版本跟踪支持，通过 version 字段实现。新增 build_includes 配置选项，支持自定义构建打包时包含的文件和目录。

默认值与约束来源于 Pydantic 模型定义，例如：
- llm.temperature ∈ [0.0, 2.0]，max_tokens ∈ [1, 128000]，context_window ∈ [1024, 256000]
- knowledge.chunk_overlap < knowledge.chunk_size（**更新**：100 < 1000）
- vectorstore.top_k ≥ 1，distance_threshold ≥ 0（**更新**：distance_threshold = 2.0）
- ui.default_theme ∈ {"dark","light"}
- **新增**：reranker.model默认"BAAI/bge-reranker-base"，支持local_path离线加载，enabled默认True，top_n默认10
- **新增**：auth.enabled默认True，min_password_length默认4，users_file默认"./data/users.json"
- **新增**：version默认"0.18.18"，表示当前应用版本
- **新增**：build_includes 默认包含 app.py、config.yaml、requirements.txt、run_app.py、logo.png、rag、ui、services、scripts、knowledge 等核心目录

### 环境变量处理
- **语法支持**：${VAR} 与 ${VAR:-默认值}
- **替换范围**：递归遍历字典/列表/字符串，仅对字符串进行替换
- **优先级**：环境变量存在时优先使用；否则使用默认值；若无默认值则保留原样
- **新增**：API密钥通过环境变量注入，config.yaml中仅保留占位符
- **新增**：本地模型路径通过环境变量覆盖，支持离线部署
- **新增**：版本号通过环境变量或配置文件统一管理
- **新增**：build_includes 配置项支持环境变量替换

### 运行时配置更新（热更新）
- **单例缓存**：get_config() 返回全局唯一实例
- **强制刷新**：reload_config() 清除缓存并重新加载，适用于运行时切换配置
- **影响范围**：UI 主题、日志与审计、向量库、预加载链、RAG链路、认证系统等
- **新增**：RerankerConfig配置变更时，RAG链路中的重排序模型会重新加载
- **新增**：API密钥变更时，LLM配置会重新加载

### 配置参数优化详情
**更新** 基于 Applied Changes，配置系统中的关键参数进行了优化：

#### 距离阈值优化
- **原值**：1.5
- **新值**：2.0
- **影响**：允许更宽松的相似度匹配，提升召回率
- **应用场景**：配合Reranker精排，先扩大候选集，再通过重排序模型精确筛选
- **数学意义**：对应余弦相似度 ≈ 0，即只要不是完全无关就保留

#### 分块大小优化
- **原值**：500
- **新值**：1000
- **影响**：支持更大的文档分块，包含更完整的函数说明和上下文
- **应用场景**：API文档需要更大的分块以包含完整函数说明
- **性能考虑**：增大分块大小会增加向量化成本，但提升检索质量

#### 分块重叠优化
- **原值**：50
- **新值**：100
- **影响**：改善文档片段间的连续性，减少跨片段信息丢失
- **应用场景**：在较大的分块基础上，增加100字符的重叠确保上下文完整性
- **平衡考虑**：重叠增加会增加向量库存储和计算开销

### 版本标准化配置示例（新增）
**新增** 统一的版本号管理机制：

```python
def _get_version() -> str:
    """从 config.yaml 读取版本号，读取失败时回退到硬编码默认值。"""
    try:
        import yaml
        from pathlib import Path
        config_path = Path(__file__).resolve().parent.parent / "config.yaml"
        if config_path.exists():
            with open(config_path, "r", encoding="utf-8") as f:
                config = yaml.safe_load(f) or {}
            return config.get("version", "0.18.18")
    except Exception:
        pass
    return "0.18.18"
```
