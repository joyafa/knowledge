================================================================================
                        专利交底书
================================================================================

【发明名称】
一种基于内容指纹的向量知识库增量构建与孤儿数据清理方法

【技术领域】
本发明涉及知识库管理与向量数据库技术领域，具体涉及一种面向向量
知识库的增量更新方法，可在向知识库目录新增、修改或删除文件后，
仅对变更文件执行向量化计算，避免全量重索引带来的计算资源浪费。

【背景技术】
现有基于向量数据库（如 ChromaDB、Milvus、Pinecone 等）的知识库
系统在文档入库时，通常采用全量扫描-全量向量化的流程：每次执行入库
操作时，系统扫描知识库目录下所有文件，无论文件是否发生过变更，均
重新执行文本提取、分块、向量嵌入和存储操作。

该方式存在以下不足：
1) 计算浪费：对于未发生任何变更的大量文件，重复执行 embedding 计算
   消耗大量 GPU/CPU 资源和时间；
2) 缺乏变更感知：系统无法区分新增文件、修改文件和未变化文件，只能
   无差别重处理；
3) 孤儿数据残留：从磁盘删除文件后，其在向量库中的历史分块不会自动
   清理，成为"孤儿数据"，影响检索精度并浪费存储空间；
4) 向量数据库原生不支持增量更新：ChromaDB 等主流向量库仅提供集合级
   的增删操作，不提供文件级的差异检测能力。

【发明内容】
本发明提出一种基于文件内容指纹（MD5/SHA256 哈希）的向量知识库增量
构建方法，核心思想是：在向量库元数据中嵌入每个文件的内容哈希值，后续
入库时通过对比磁盘文件哈希与向量库存储哈希，识别变更文件子集，仅对
该子集执行向量化操作，同时自动清理已删除文件对应的孤儿分块。

技术方案包括以下步骤：

S1）初始化/全量模式（首次运行或显式指定）：
    - 扫描知识库目录下所有支持的文件；
    - 对每个文件计算内容 MD5 哈希；
    - 加载、分块、向量化所有文件；
    - 将 content_hash 字段写入每个分块的 ChromaDB metadata 中；

S2）增量模式（后续运行，默认模式）：
    S2.1）扫描磁盘目录，计算每个文件的 MD5 哈希 → current_hashes；
    S2.2）从向量库 metadata 中提取已存储的文件哈希 → stored_hashes；
    S2.3）逐文件对比哈希值：
          - current 中有、stored 中无 → 新增文件（new_files）
          - 两边都有但哈希不同 → 变更文件（changed_files）
          - 两边都有且哈希相同 → 未变化文件（跳过）
    S2.4）孤儿检测：stored 中有、current 中无 → 已删除文件，
          对孤儿文件的所有分块执行向量库删除操作；

S3）增量入库：
    S3.1）仅对新增文件和变更文件执行文本加载与分块；
    S3.2）对变更文件，先删除其在向量库中的旧分块（按 source + chunk_index 定位）；
    S3.3）对新增和变更文件的新分块执行 embedding 计算并写入向量库，
          同时将新的 content_hash 写入 metadata；

S4）全量重建模式（使用 --full 参数触发）：
    直接执行 S1 流程，适用于哈希算法变更或数据修复场景。

【有益效果】
1) 大幅减少重复计算：仅对变更文件执行 embedding，99% 以上场景下
   计算量降低至全量模式的 1%~5%；
2) 自动孤儿清理：删除文件后无需手动维护，系统自动移除其历史分块，
   确保检索结果不会引用已不存在的文档；
3) 零配置增量：默认即为增量模式，用户无需额外配置或学习；
4) 兼容全量重建：通过命令行参数可随时触发全量重建，灵活应对异常；
5) 存储开销极小：每个分块仅增加 32 字节的 MD5 哈希存储。

【具体实施方式】
以"诊断软件智能问答系统"为例：

知识库目录包含 604 个 Markdown 文档（约 15 万行），首次全量入库耗时约
8 分钟。用户随后新增 2 个 PDF 技术手册。

传统方式：重新扫描 606 个文件 → 重新分块 → 重新向量化 → 耗时约 8 分钟

本发明方式：
步骤 1：扫描目录 606 个文件 → 计算哈希 → 606 次 MD5；
步骤 2：从向量库提取 604 个文件的已存哈希；
步骤 3：对比哈希 → 604 个未变，2 个新增 → 变更集 = {manual1.pdf, manual2.pdf}；
步骤 4：检测孤儿 → 0 个；
步骤 5：仅加载 2 个 PDF → 分块 47 个 → embedding 47 次 → 写入向量库；
步骤 6：完成，耗时约 15 秒（仅占全量模式的 3%）。
