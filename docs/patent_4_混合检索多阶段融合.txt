                        专利交底书

【发明名称】
一种基于语义-关键词双路召回与交叉编码器精排的RAG多阶段检索方法

【技术领域】
本发明涉及信息检索与自然语言处理领域，具体涉及一种面向检索增强生成
（RAG）系统的多阶段混合检索方法，通过语义向量检索与关键词检索双路
召回、无监督融合以及交叉编码器精排，在保证召回率的同时提升检索精度。

【背景技术】
RAG 系统的检索质量直接决定最终生成回答的准确性。现有方案通常分为三类：

1) 纯向量检索：基于 dense embedding 进行语义匹配，对同义词和语义相近
   的查询效果好，但对精确术语匹配（如故障码、API 名称）的召回能力弱；
2) 纯关键词检索（如 BM25、TF-IDF）：对精确匹配效果好，但无法理解语义
   相似的表达，用户使用口语化查询时容易漏召回；
3) 混合检索：同时使用向量检索和关键词检索，但面临两个核心挑战：
   a) 如何融合两路不同量纲的排序结果？（向量的 L2 距离 vs 关键词的 BM25 分数）
   b) 融合后的排序是否足够精准？是否需要进一步的精排？

现有的融合方案多采用加权求和（需要人工调参寻找最优权重）或简单拼接
（丢失排序信息），且缺乏精排阶段对最终结果进行语义级校验。

【发明内容】
本发明提出一种三阶段 RAG 检索方法——语义+关键词双路召回、RRF 无监督
融合、Cross-Encoder 精排——实现从粗到细的检索精度逐级提升。

技术方案包括以下步骤：

S1）双路并行召回（粗召回阶段）：
    S1.1）语义向量检索：以用户查询的 embedding 向量在 ChromaDB 中
          执行 ANN（近似最近邻）检索，返回 top_k 个向量相似文档，
          记录每个结果的 L2 距离（distance 字段）；
    S1.2）关键词检索（BM25）：基于 jieba 分词对查询进行中文分词，
          在全部文档原文上执行 BM25 评分，返回 top_k 个关键词匹配文档；
    
S2）向量结果阈值过滤：
    对向量检索结果按配置的 distance_threshold（如 2.0）进行后过滤，
    剔除 L2 距离过大的低质结果；若过滤后结果集为空，保留原始向量
    候选参与融合（避免全部丢弃导致召回断层）；

S3）RRF（Reciprocal Rank Fusion）无监督融合：
    对向量候选集 R_vector 和 BM25 候选集 R_bm25 执行倒数秩融合：
    
    score(d) = Σ 1/(k + rank_i(d))
    
    其中 rank_i(d) 是文档 d 在第 i 个排序列表中的排名，k 为平滑常数
    （默认 k=60）。该融合方式无需任何权重调参，直接基于排名位置
    进行无监督融合，输出统一的文档排序列表。

S4）Cross-Encoder Reranker 精排（精排阶段）：
    对 RRF 融合后的前 top_n（如 10）个候选文档，使用 Cross-Encoder
    模型（如 BAAI/bge-reranker-base）对每对 (query, document) 进行
    联合编码，输出相似度分数，按分数降序重排：
    
    sim = CrossEncoder(query, doc_i)  ∀ doc_i ∈ top_n_candidates
    
    Cross-Encoder 相比双塔模型（Bi-Encoder）的优势在于：查询和文档
    在同一编码器内交互计算注意力，能捕捉更细粒度的语义匹配关系。

S5）LLM 生成阶段：
    将精排后的 top_k 个文档与系统提示词、对话历史拼接为 prompt，
    送入大语言模型生成最终回答，附带回溯到源文档的引用标注。

【有益效果】
1) 双路互补召回：语义检索覆盖同义表达，BM25 覆盖精确术语，召回率
   显著优于任一单路方案；
2) RRF 零参融合：无需手工调权或训练融合模型，即插即用；
3) 精排质量跃升：Cross-Encoder 将排名精度（NDCG@5）在粗排基础上
   提升 15%～25%（经验值）；
4) 弹性降级：Reranker 模型加载失败或 disabled 时自动退化为纯 RRF
   结果，不影响系统可用性；
5) 可配置颗粒度：各阶段参数（top_k、distance_threshold、top_n）
   均可通过配置文件独立调整，适配不同知识库规模和质量需求。

【具体实施方式】
以"诊断软件智能问答系统"为例：

查询："氧传感器故障码 P0135 怎么办"

步骤 1（双路召回）：
  - 向量检索 top_5：4 个相关文档，L2 距离 0.3~1.8；
  - BM25 检索 top_5：3 个相关文档（含"P0135"精确匹配的维修手册段落）；

步骤 2（阈值过滤）：
  distance_threshold=2.0，5 个向量结果全部通过；

步骤 3（RRF 融合）：
  向量排名:  doc_A(1), doc_B(2), doc_C(3), doc_D(4), doc_E(5)
  BM25排名:  doc_B(1), doc_F(2), doc_A(3), doc_C(4), doc_G(5)
  
  RRF 计算（k=60）：
  doc_A: 1/(60+1) + 1/(60+3) = 0.0164 + 0.0159 = 0.0323
  doc_B: 1/(60+2) + 1/(60+1) = 0.0161 + 0.0164 = 0.0325
  …
  融合后排序：doc_B(0.0325) > doc_A(0.0323) > doc_C > doc_F > doc_D > doc_E > doc_G

步骤 4（精排）：
  取前 top_n=10 个候选 → Cross-Encoder 逐对打分：
  (query, doc_B) → score=0.89
  (query, doc_A) → score=0.92
  (query, doc_C) → score=0.45
  …
  精排后：doc_A(0.92) > doc_B(0.89) > doc_C(0.45) > …

步骤 5（生成）：
  取 top 3 文档拼接 prompt → LLM 生成回答 "P0135 表示氧传感器加热器电路
  故障，建议… [来源: manuals/维修手册.pdf, specs/OBD-II协议规范.docx]"
