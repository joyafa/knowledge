# 技术交底书

## 发明名称

一种面向源代码与混合格式文档的知识库构建与智能分块方法

---

## 一、技术领域

本发明涉及文档处理与知识库构建领域，具体涉及一种针对包含源代码片段的技术文档进行代码块完整性保护的语义分块方法，以及面向中文 Windows 环境下多编码源码文件的自动编码探测方法。

---

## 二、背景技术

在构建面向软件开发团队的智能问答知识库时，知识库中通常需要同时收录 Markdown 格式的技术文档、纯文本格式的说明文件、PDF 格式的规范文档，以及 C/C++ 源代码和头文件。将这些不同格式的文档切分为适当大小的文档块并存入向量数据库，是检索增强生成系统的前置步骤。

现有的文档分块方法主要存在以下不足：

**（1）代码块被截断破坏语法完整性。** 常见的分块策略按固定字符数或段落边界切分文档。当切分点恰好落在代码块内部时，一个完整的函数定义或类声明会被拆分为两个不完整的片段。检索到的不完整代码片段缺乏上下文，大语言模型无法基于残缺的代码给出准确的 API 用法说明。

**（2）中文环境下源码文件编码多样。** 在中文 Windows 系统中，C/C++ 源码文件的编码格式不统一：部分文件采用 UTF-8 编码（现代工具链生成），部分文件采用 GBK 或 GB2312 编码（旧版 IDE 如 Visual Studio 6.0 生成），还有部分文件采用 GB18030 编码。现有方案通常默认使用 UTF-8 编码读取所有文件，当遇到非 UTF-8 编码的中文注释时，要么直接报错中断处理流程，要么产生乱码导致后续语义检索失效。

**（3）分块重叠区跨越代码块边界。** 为保证检索时上下文完整性，相邻文档块之间通常保留一定长度的重叠区域。但现有方案在确定重叠区域时不考虑代码块边界，导致重叠区域可能从一个代码块的中间开始，引入额外的语法不完整片段。

---

## 三、发明目的

本发明的目的在于克服上述现有技术的不足，提供一种在文档分块过程中追踪代码块边界以保护代码完整性的两遍分块方法，以及面向中文多编码环境按优先级链自动探测文件编码的方法，使知识库中的源代码片段保持语法完整、中文内容正确显示。

---

## 四、技术方案

### 4.1 总体流程

本发明包含两个相互独立又协同工作的子方法：

**子方法一：代码块完整性保护的两遍语义分块方法**

**子方法二：多编码自动探测与兼容读取方法**

### 4.2 子方法一：代码块完整性保护的两遍语义分块方法

该方法对输入文档执行两遍扫描，在两遍扫描中均追踪代码块边界，确保任何情况下代码块不被拆分。

**(1) 第一遍：基于标题层级的语义切分。**

系统按行遍历文档内容，维护一个代码块状态标记（用于标识当前是否处于代码块内部）。代码块的边界由连续三个反引号标记界定。

- 当代码块状态为"外部"时，若当前行以二级标题标记（##）开头，则将此前累积的内容作为一个独立章节，同时开始新的章节缓冲区；
- 当代码块状态为"内部"时，即使当前行以二级标题标记开头，也不进行切分，该行继续累积至当前章节缓冲区；
- 每遇到连续三个反引号标记，切换代码块状态。

每个切分出的章节携带其所属的标题文本作为上下文元数据。

**(2) 第二遍：超长章节的段落级精细切分。**

对于第一遍切分后长度仍超过预设阈值的章节，系统执行第二遍精细切分：

- 将章节内容按连续两个换行符（段落边界）拆分为段落单元；
- 再次维护代码块状态标记，在第二遍中同样追踪代码块边界；
- 从第一个段落单元开始逐个累积，计算累积后的总长度；
- 当累积长度即将超过阈值，且当前不处于代码块内部时，将已累积的段落作为一个文档块输出，并开始下一个文档块的累积；
- 当累积长度即将超过阈值，但当前处于代码块内部时，不执行切分，继续累积直至代码块结束；
- 相邻文档块之间保留重叠区域，重叠区域的内容从当前文档块的末尾若干段落单元中取用，但重叠区域不以代码块中间的段落为起点。

**(3) 元数据标注。** 每个最终输出的文档块记录以下元数据：来源文件路径、所属标题、块序号、文件类型标识。

### 4.3 子方法二：多编码自动探测与兼容读取方法

**(1) 编码探测优先级链。** 系统预设一个编码尝试的优先级序列，从高到低依次为：

- 第一优先级：UTF-8（国际标准 Unicode 编码，现代工具链默认编码）；
- 第二优先级：GBK（中文 Windows 系统默认编码，常见于旧版 IDE 生成的源码）；
- 第三优先级：GB2312（中文国家标准基础编码集）；
- 第四优先级：GB18030（中文国家标准扩展编码集，GBK 的超集）；
- 第五优先级：Latin-1（西欧字符集，可无损接收任意单字节数据，作为最终兜底）。

**(2) 逐级探测过程。** 系统将文件内容读取为原始字节序列（不指定编码），然后按优先级从高到低依次尝试用每种编码对字节序列进行解码：

- 若当前编码解码成功（未产生解码异常），则采用该编码作为文件的实际编码，返回解码后的文本内容；
- 若当前编码解码失败（产生解码异常或字符查找异常），则跳过该编码，继续尝试下一优先级的编码。

**(3) 兜底处理。** 若所有编码均尝试后仍未成功（理论情况下不会发生，因为 Latin-1 可接收任意单字节数据），则使用 UTF-8 编码并启用错误替换模式——将无法解码的字节替换为 Unicode 替换字符，确保流程不会中断。

**(4) 应用范围。** 该编码探测方法应用于以下场景：

- 文档入库时的文件内容读取；
- 知识库文件元数据提取时的标题识别；
- 文件列表展示时的文件名解析。

### 4.4 支持的文档格式

本方法支持以下文档格式的自动识别与处理：

| 文档类型 | 扩展名 | 处理方式 |
|:--------:|:------:|:---------|
| Markdown 文档 | .md | 标题切分 + 段落精切 |
| 纯文本文件 | .txt | 段落精切 |
| PDF 文档 | .pdf | 专用解析器提取文本后切分 |
| C/C++ 源文件 | .c, .cc, .cpp, .cxx | 多编码探测 + 段落精切 |
| C/C++ 头文件 | .h, .hpp, .hxx | 多编码探测 + 段落精切 |

## 五、有益效果

采用本发明所述方法，与现有技术相比，具有以下有益效果：

**（1）代码块语法完整性得到保障。** 两遍分块过程中持续追踪代码块边界，确保切分点不会落在代码块内部，使得每个文档块中的代码片段均保持语法完整，检索系统和大语言模型可以正确理解和引用代码内容。

**（2）中文 Windows 环境兼容性好。** 多编码自动探测方法按优先级链逐级尝试解码，覆盖了中文 Windows 环境下主流的编码格式，无需用户手动指定文件编码，实现"打开即用"的体验。

**（3）重叠区不引入额外代码碎片。** 分块重叠区域的起止位置也受代码块边界约束，避免在重叠区引入额外的语法不完整片段。

**（4）处理流程健壮不中断。** 编码探测链以 Latin-1 和错误替换模式作为兜底，确保任何编码的文件都能被成功读取，不会因编码问题中断整个文档入库流程。

## 七、具体实施方式

### 实施例

以一份包含 C++ 代码示例的 Markdown 格式 API 文档为例，说明本发明的具体实施过程。

**文档内容示例：**

```
## TcpClient 类

TcpClient 是一个异步 TCP 客户端封装。

### 构造函数

```cpp
TcpClient(EventLoop* loop, const InetAddress& serverAddr);
```

### 发送数据

```cpp
void send(const std::string& message);
void send(const void* data, size_t len);
```

该函数支持两种调用方式：字符串和原始字节。

### 连接管理

void connect();
void disconnect();
```

**步骤 1 — 第一遍标题切分。**

系统按行扫描，识别到三个二级标题（##）边界，将文档切分为三个章节：

- 章节 A："TcpClient 类"（含构造函数说明和代码）
- 章节 B："发送数据"（含 send 函数说明和代码）
- 章节 C："连接管理"（含 connect/disconnect 函数说明）

在扫描过程中，章节 B 内出现连续三个反引号标记时，代码块状态切换为"内部"。当代码块内部出现 `void send` 等看起来像标题的行时，由于代码块状态为"内部"，不触发切分。

**步骤 2 — 长度检查。** 假设章节 A 长度为 800 字符，低于阈值 1000，作为独立文档块输出。章节 B 长度为 450 字符，同样直接输出。

**步骤 3 — 第二遍精细切分。**（仅在章节超长时触发）

假设阈值调整为 300 字符，章节 B 需要精切。系统按段落边界切分后发现第一个段落单元为代码块，不切分，继续累积至代码块结束。最终章节 B 作为一个完整文档块输出，代码块未被拆分。

**步骤 4 — 编码探测。**

该文件以 UTF-8 编码存储，第一优先级 UTF-8 解码成功，直接返回内容。

若该文件由旧版 Visual Studio 生成，采用 GBK 编码，则 UTF-8 解码失败，GBK 解码成功，返回正确的中文内容。

## 八、权利要求书（草案）

**权利要求 1.** 一种面向源代码与混合格式文档的知识库智能分块方法，其特征在于，包括以下步骤：

S1. 按行遍历文档内容，维护代码块状态标记，当处于代码块外部且遇到标题标记时执行切分，当处于代码块内部时跳过切分；

S2. 对切分后长度仍超过预设阈值的章节，按段落边界进一步切分，在切分过程中同样维护代码块状态标记，当即将执行切分且当前处于代码块内部时不执行切分，继续累积直至代码块结束；

S3. 相邻文档块之间保留重叠区域，重叠区域的起始位置不在代码块的中间。

**权利要求 2.** 根据权利要求 1 所述的方法，其特征在于，步骤 S1 和 S2 中所述代码块状态标记的维护方式为：在遍历过程中检测代码块起始标记和结束标记，遇到起始标记时将状态切换为"内部"，遇到结束标记时将状态切换为"外部"。

**权利要求 3.** 一种面向多编码源码文件的自动编码探测方法，其特征在于，包括以下步骤：

将文件内容读取为原始字节序列；按照预设的编码优先级序列，从高到低依次尝试用每种编码对字节序列进行解码；首个解码成功的编码即为文件的实际编码。

**权利要求 4.** 根据权利要求 3 所述的方法，其特征在于，所述编码优先级序列依次为：UTF-8、GBK、GB2312、GB18030、Latin-1。

**权利要求 5.** 根据权利要求 3 所述的方法，其特征在于，当所有编码均尝试后仍未成功时，使用 UTF-8 编码并启用错误替换模式，将无法解码的字节替换为 Unicode 替换字符。

**权利要求 6.** 一种知识库构建系统，其特征在于，包括：

- 代码块完整性保护分块模块，用于在文档分块过程中追踪代码块边界，确保切分点不落在代码块内部；
- 多编码自动探测模块，用于按编码优先级链自动探测文件编码并读取文件内容。

**权利要求 7.** 一种计算机可读存储介质，其上存储有计算机程序，其特征在于，所述程序被处理器执行时实现权利要求 1 至 5 中任一项所述的方法。
