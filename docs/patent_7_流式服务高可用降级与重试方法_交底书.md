# 技术交底书

## 发明名称

一种大语言模型流式服务的高可用降级与指数退避重试方法

---

## 一、技术领域

本发明涉及大语言模型调用与服务高可用领域，具体涉及一种针对大语言模型流式调用场景的自适应降级与指数退避重试方法。

---

## 二、背景技术

在检索增强生成系统中，用户提出问题后，系统需要调用大语言模型（LLM）生成回答。流式调用（Server-Sent Events）是当前主流的 LLM 调用方式，服务器逐个令牌（Token）地返回生成内容，用户界面实时显示每个令牌，实现"打字机效果"的用户体验。

现有方案在 LLM 调用的可靠性方面存在以下不足：

**（1）流式调用不稳定时无降级手段。** 流式调用依赖于长连接和服务器推送机制，对网络质量和服务器处理能力要求较高。当网络波动、代理服务器不支持流式传输、或 LLM 服务端负载过高时，流式调用容易失败。现有方案在流式失败后直接向用户返回错误信息，用户无法获得任何回答。

**（2）缺乏智能重试策略。** 当 LLM 调用失败时，部分方案采用固定间隔重试，短时间内发送大量请求可能触发服务端的频率限制（Rate Limiting），导致后续请求也被拒绝，形成"雪崩效应"。部分方案不提供重试，偶发的网络抖动即导致用户请求失败。

**（3）空响应未被视为异常。** 大语言模型有时会返回结构正常但内容为空的响应（例如返回了完整的响应框架但生成内容字段为空）。现有方案将这类空响应当作成功处理，用户界面显示空白回答，体验不佳。

---

## 三、发明目的

本发明的目的在于克服上述现有技术的不足，提供一种在大语言模型流式调用失败时自动降级为非流式调用、配合指数退避重试策略、并检测空响应的 LLM 服务高可用方法，使系统在面对网络波动和服务端异常时仍能向用户提供有效的回答。

---

## 四、技术方案

### 4.1 总体流程

本发明提出的 LLM 服务高可用方法包含一条递进式降级链路：

```
流式调用 → 重试 → 降级为非流式调用 → 重试 → 结构化错误
```

### 4.2 流式调用与重试

**(1) 首次调用。** 系统优先采用流式方式调用大语言模型 API，将请求参数中的流式标志设为启用。系统逐个接收服务器推送的响应片段，每收到一个包含有效内容字段的片段，即将该内容实时传递给用户界面显示。

**(2) 空响应检测。** 在流式响应接收完毕后，系统检查是否实际接收到了有效内容。具体方法为维护一个内容接收标记，初始值为"未接收"，每接收到一个有效内容片段即将标记更新为"已接收"。若响应接收完毕后标记仍为"未接收"，则判定为空响应，将其视为调用失败。

**(3) 指数退避重试。** 当流式调用发生异常（网络错误、超时、空响应等）时，系统启动重试机制：

- 设定最大重试次数（如 3 次）；
- 每次重试的等待间隔按指数增长：第 1 次重试等待 2 的 1 次方秒，第 2 次等待 2 的 2 次方秒，以此类推；
- 每次重试均携带完整的请求参数和消息上下文，不丢失对话历史。

在等待间隔期间，系统不向 LLM 服务端发送新请求，避免因短时间内大量重试触发服务端的频率限制。

**(4) 重试轮次结束。** 当所有重试轮次耗尽仍未成功时，系统记录最后一次异常信息，进入降级阶段。

### 4.3 降级为非流式调用

**(1) 降级触发。** 当流式调用的所有重试轮次均失败后，系统自动切换为非流式调用方式。

**(2) 非流式调用。** 系统将请求参数中的流式标志设为禁用，使用与流式调用相同的消息上下文和模型参数，发送非流式 API 请求。服务器一次性返回完整的生成内容。

**(3) 非流式空响应检测。** 系统检查非流式响应中的内容字段是否为空或不存在。若内容为空，判定为调用失败。

**(4) 非流式结果处理。** 若非流式调用成功且内容非空，将完整内容一次性返回给用户界面（用户体验从"打字机效果"变为"一次性显示"，但内容完整）。

### 4.4 最终错误处理

当非流式调用也失败时，系统执行以下操作：

**(1) 构建结构化错误信息。** 错误信息包含以下字段：

- 错误类型标识（如"模型调用失败"）；
- 调用的模型名称；
- 错误详情（最后一次异常的错误消息）；
- 重试次数。

**(2) 审计日志记录。** 系统将完整的调用失败信息写入审计日志，包括：用户查询内容、调用时间、重试次数、各次重试的错误详情、最终失败原因。供运维人员事后分析和排查。

**(3) 用户通知。** 向用户界面返回友好的错误提示，告知用户当前无法获取回答，建议稍后重试或检查配置。

### 4.5 完整降级链路

系统的完整降级链路如下：

1. 首次流式调用 → 成功则流式输出；
2. 首次流式调用失败 → 等待 2 秒 → 第 1 次重试流式调用；
3. 第 1 次重试失败 → 等待 4 秒 → 第 2 次重试流式调用；
4. 第 2 次重试失败 → 降级为非流式调用；
5. 非流式调用成功 → 全文输出；
6. 非流式调用失败 → 返回结构化错误信息并记录审计日志。

## 五、有益效果

采用本发明所述方法，与现有技术相比，具有以下有益效果：

**（1）自动降级保障服务连续性。** 流式调用不可用时自动切换至非流式调用，在牺牲实时显示效果的前提下保证用户能够获得完整的回答内容，避免服务完全中断。

**（2）指数退避避免雪崩效应。** 重试间隔按指数增长，避免短时间内向服务端发送大量请求导致频率限制触发，保护服务端和客户端双方。

**（3）空响应检测提升可靠性。** 将空响应纳入异常处理范畴，避免向用户显示空白内容，提升用户体验。

**（4）审计日志提供可观测性。** 每次调用失败均记录详细的审计信息，运维人员可据此分析故障模式、评估服务质量和优化重试策略。

## 七、具体实施方式

### 实施例

以某车载诊断系统的智能问答场景为例，说明本发明的具体实施过程。

**实施例一：正常流式响应**

用户提交查询："CAN 总线初始化失败如何排查"。系统以流式方式调用 LLM API，逐个接收响应片段并实时显示在用户界面。接收完毕后，内容接收标记为"已接收"，判定为成功，用户看到完整的排查步骤。

**实施例二：流式超时后重试成功**

用户提交查询后，首次流式调用因网络波动超时。系统等待 2 秒后执行第 1 次重试。重试成功，流式输出完整内容。用户感受到约 2 秒的额外延迟，但获得了完整回答。

**实施例三：流式失败后降级为非流式**

用户提交查询后，首次流式调用返回空响应。系统等待 2 秒后重试，仍为空响应。再次等待 4 秒后重试，网络超时。三次流式调用均失败。

系统自动降级为非流式调用，发送请求后等待服务器一次性返回完整内容。非流式调用成功，用户一次性看到完整回答（无打字机效果）。

**实施例四：全部失败**

用户提交查询后，三次流式调用均超时，非流式调用也超时。系统构建结构化错误信息："模型调用失败：glm-4-flash 模型响应超时，已重试 3 次"，写入审计日志，向用户显示"当前服务暂时不可用，请稍后重试"。

## 八、权利要求书（草案）

**权利要求 1.** 一种大语言模型流式服务的高可用降级与重试方法，其特征在于，包括以下步骤：

S1. 以流式方式调用大语言模型 API，逐个接收响应片段并实时传递给用户界面，同时维护内容接收标记以检测是否实际接收到有效内容；

S2. 当流式调用发生异常时，按指数增长的间隔执行多次重试，每次重试携带完整的请求参数和消息上下文；

S3. 当流式调用的所有重试均失败后，自动切换为非流式调用方式，将请求参数中的流式标志设为禁用，等待服务器一次性返回完整内容；

S4. 当非流式调用也失败时，构建包含模型名称、错误详情和重试次数的结构化错误信息，写入审计日志并向用户返回错误提示。

**权利要求 2.** 根据权利要求 1 所述的方法，其特征在于，步骤 S1 中所述空响应检测为：在流式响应接收完毕后检查内容接收标记，若标记指示未接收到有效内容，则将该次调用判定为失败并纳入重试流程。

**权利要求 3.** 根据权利要求 1 所述的方法，其特征在于，步骤 S2 中所述指数增长的间隔为：第 n 次重试的等待时间为 2 的 n 次方秒。

**权利要求 4.** 根据权利要求 1 所述的方法，其特征在于，步骤 S4 中所述审计日志包含：用户查询内容、调用时间戳、各次重试的错误详情和重试次数。

**权利要求 5.** 一种计算机可读存储介质，其上存储有计算机程序，其特征在于，所述程序被处理器执行时实现权利要求 1 至 4 中任一项所述的方法。
